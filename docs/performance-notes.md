## 热加载优化

以下为同轮历史对照，非 README 最新结果。优化前整表转 Arrow、每次请求强制 GC；优化后序列化对象驻留 R、仅传输当前页。fst 始终按行读取，收益来自取消前台强制 GC。单位：ms。

| 格式 | 优化前 | 优化后 | 耗时降低 |
|---|---:|---:|---:|
| fst | 50.5 | 15.4 | 69.5% |
| qdata | 396.3 | 228.7 | 42.3% |
| qs2 | 477.0 | 288.7 | 39.5% |
| rda | 821.9 | 614.4 | 25.2% |
| rds | 734.2 | 650.1 | 11.5% |

## R 进程内存

macOS ARM64、arf 的一次测量：加载 arrow/data.table 后 RSS 约 235 MiB；解码 `big.rds` 后约 350 MiB，释放对象并 GC 后仍约 350 MiB。这是进程内存，受环境与历史峰值影响，不是对象大小或内存上限。

## 临时文件与管道直传

**管道直传仍是测试原型，生产实现未切换。** 二进制输出使用 `/dev/stdout`，仅在 macOS 验证，Windows 尚未适配。

将 `big.rds` 解码为同一份 R 内存表，对照三种页传输方式。单位：ms。

| 每页行数 | 临时 Arrow | 二进制 Arrow 管道 | JSON 管道 | 二进制较文件耗时降低 |
|---|---:|---:|---:|---:|
| 500 | 3.11 | 2.15 | 1.85 | 30.8% |
| 5,000 | 12.51 | 11.03 | 14.40 | 11.8% |
| 50,000 | 103.73 | 102.21 | 163.28 | 1.5% |

二进制管道每页节省约 1–1.5 ms；500 行时 JSON 略快，大页时 Arrow 更快。该收益不等于原文件加载收益。

### 方法与边界

- 共用 4 字节小端长度帧协议，轮换执行顺序；两种 Arrow 均用 ZSTD。
- 每种页大小在首／中／尾各测 15 次，预热后合并 45 次取中位数。
- 包含 R 编码、进程通信、JS 解码及临时文件创建与清理；不含 R 启动、原文件解码、界面通信、绘制和断言。
- 逐值核对日期、缺失值、大整数、Unicode 和规范化列表列；JSON 使用 `digits = 17`。
- 二进制按 Buffer 分帧，不转字符串、不反复拼接已有负载；并非共享内存或零拷贝。

原始样本、逐位置中位数及 P95：`data/test-perform-transport.json`。

```bash
RDATA_PERF=1 RDATA_TEST_R=arf npx vitest run tests/test-perform-transport.test.ts
```
